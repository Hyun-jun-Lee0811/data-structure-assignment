# [자료구조2] Assignment 02 - 2026.09.18

## 과제

괄호 표기법으로 입력받은 이진트리를 **배열 기반 이진트리**와 **포인터 연결 자료구조 기반 이진트리**로 각각 구성하여 트리의 계층적 출력, 전체 노드 수, 단말/비단말 노드 수, 높이와 차수를 계산하고, 완전 이진트리 & 포화 이진트리 & 편향 이진트리 여부를 판별하는 프로그램을 구현하였다.

또한 두 구현 방식의 메모리 사용량을 비교하고, 특정 노드를 입력하여 해당 노드의 자식,부모,형제를 조회하는 방식의 차이를 비교하였다.

---

## 구현 내용

### 1. 괄호 표기법을 이용한 이진트리 입력

이전 과제와 동일하게 괄호 표기법을 사용하여 트리를 입력받는다.

이진트리는 각 노드의 왼쪽 자식과 오른쪽 자식을 구분하므로 다음과 같은 형태로 입력한다.

```text
A(B(D,E),C)
```

왼쪽 또는 오른쪽 자식이 없는 경우에는 해당 위치를 비워 입력할 수 있다.

```text
A(,B)
A(B,)
```

입력받은 문자열을 이용하여 동일한 트리를 배열 구현과 연결 자료구조 구현으로 각각 생성하였다.

---

### 2. 배열 기반 이진트리 구현

배열 기반 구현에서는 이진트리의 부모와 자식 관계를 배열의 인덱스로 표현하였다.

루트 노드를 1번 인덱스에 저장하고, 각 노드의 왼쪽 자식과 오른쪽 자식은 다음과 같은 규칙으로 저장하였다.

```text
왼쪽 자식 : 부모 인덱스 × 2
오른쪽 자식 : 부모 인덱스 × 2 + 1
```

예를 들어 노드 A가 1번 인덱스에 있다면 B는 2번, C는 3번 인덱스에 저장된다.

```c
printArrayTree(index * 2, depth + 1);
printArrayTree(index * 2 + 1, depth + 1);
```

배열의 각 원소에는 노드 이름과 해당 위치가 사용 중인지 확인하기 위한 `used` 값을 저장하였다.

```c
typedef struct {
    char name[MAX_NAME];
    int used;
} ArrayNode;
```

### 3. 포인터 연결 자료구조 기반 이진트리 구현

연결 자료구조 구현에서는 각 노드를 구조체로 생성하고 왼쪽 자식과 오른쪽 자식을 포인터로 연결하였다.

```c
typedef struct TreeNode {
    char name[MAX_NAME];
    struct TreeNode* left;
    struct TreeNode* right;
} TreeNode;
```

각 노드는 동적으로 메모리를 할당하고, 입력된 괄호 표기법에 따라 `left`와 `right` 포인터를 연결하였다.

트리 사용이 끝난 후에는 후위 순회 방식으로 모든 노드를 해제하여 동적으로 할당한 메모리를 정리하였다.

```c
static void freeLinked(TreeNode* node)
{
    if (node == NULL)
        return;

    freeLinked(node->left);
    freeLinked(node->right);
    free(node);
}
```

### 4. 계층적 이진트리 출력

배열 구현과 연결 자료구조 구현 모두 재귀 함수를 이용하여 트리를 계층적으로 출력하였다.

노드의 깊이에 따라 들여쓰기를 추가하여 부모와 자식 관계를 확인할 수 있도록 구현하였다.

```c
static void printArrayTree(int index, int depth)
{
    if (arrayExists(index) == 0)
        return;

    printIndent(depth);
    printf("%s\n", arrayTree[index].name);

    printArrayTree(index * 2, depth + 1);
    printArrayTree(index * 2 + 1, depth + 1);
}
```

연결 자료구조에서는 각 노드의 `left`, `right` 포인터를 이용하여 동일한 방식으로 출력하였다.

```c
static void printLinkedTree(TreeNode* node, int depth)
{
    if (node == NULL)
        return;

    printIndent(depth);
    printf("%s\n", node->name);

    printLinkedTree(node->left, depth + 1);
    printLinkedTree(node->right, depth + 1);
}
```

### 5. 전체 노드 수, 단말/비단말 노드 수, 높이, 차수 계산

두 구현 방식에서 각각 다음 정보를 계산하도록 구현하였다.

* 전체 노드 수
* 단말 노드 수
* 비단말 노드 수
* 트리의 높이
* 트리의 차수

배열 구현에서는 배열 인덱스를 순회하면서 `used` 값을 확인하고 자식 인덱스를 이용하여 자식 수를 계산하였다.

```c
static int arrayChildCount(int index)
{
    int count = 0;

    if (arrayExists(index * 2) == 1)
        count++;

    if (arrayExists(index * 2 + 1) == 1)
        count++;

    return count;
}
```

연결 자료구조에서는 각 노드의 `left`, `right` 포인터가 `NULL`인지 확인하여 자식 수를 계산하였다.

높이는 왼쪽 서브트리와 오른쪽 서브트리 중 더 큰 높이에 1을 더하는 재귀 방식으로 계산하였다.

```c
if (left > right)
    return left + 1;

return right + 1;
```

트리의 차수는 모든 노드가 가질 수 있는 자식 수 중 최댓값으로 계산하였다.

### 6. 이진트리 형태 판별

입력된 이진트리가 다음 세 가지 형태에 해당하는지 판별하였다.

* 완전 이진트리
* 포화 이진트리
* 편향 이진트리

#### 완전 이진트리

배열 인덱스 특성을 이용하여 노드가 1번부터 전체 노드 수까지 빈 공간 없이 배치되어 있는지 확인하였다.

```c
if (arrayTree[i].used == 1 && i > count)
    return 0;
```

연결 자료구조에서는 각 노드에 배열 기반 인덱스를 부여하여 해당 인덱스가 전체 노드 수를 초과하는지를 재귀적으로 검사하였다.

---

#### 포화 이진트리

트리의 높이를 기준으로 포화 이진트리에서 필요한 전체 노드 수를 계산한 후, 실제 노드 수와 비교하였다.

```c
int full = (1 << height) - 1;

if (arrayIsComplete() == 1 && count == full)
    return 1;
```

연결 자료구조에서도 동일한 기준을 사용하여 포화 이진트리 여부를 판별하였다.

---

#### 편향 이진트리

모든 노드의 자식 수가 1 이하인지 확인하여 편향 이진트리 여부를 판별하였다.

```c
if (arrayDegree() <= 1)
    return 1;
```

연결 자료구조에서도 각 노드의 최대 자식 수를 계산하여 동일한 기준으로 판별하였다.

### 7. 배열 구현과 연결 구현의 메모리 사용량 비교

두 구현 방식에서 하나의 노드가 차지하는 구조체 크기를 `sizeof()`를 이용하여 확인하고, 입력된 트리에 필요한 표현 공간을 계산하였다.

배열 구현에서는 사용되는 배열 인덱스 범위를 기준으로 필요한 공간을 계산하였다.

```c
long arrayBytes =
    (long)slots * (long)sizeof(ArrayNode);
```

연결 자료구조에서는 실제 생성된 노드의 개수와 노드 하나의 크기를 이용하여 필요한 공간을 계산하였다.

```c
long linkedBytes =
    (long)count * (long)sizeof(TreeNode);
```

이를 이용하여 일반 이진트리, 완전 이진트리, 편향 이진트리 등의 형태에서 두 구현 방식의 메모리 사용량 차이를 비교하였다.

특히 배열 기반 구현은 트리의 형태에 따라 실제 노드가 없는 배열 공간이 발생할 수 있으며, 편향된 트리에서는 인덱스가 크게 증가하여 빈 공간이 많아질 수 있다. 반면 연결 자료구조는 실제 노드가 존재하는 만큼만 노드를 동적으로 생성하므로 트리의 형태와 관계없이 필요한 노드 수만큼 메모리를 사용한다.

### 8. 특정 노드의 자식 / 부모 / 형제 조회

사용자가 특정 노드의 이름을 입력하면 배열 구현과 연결 자료구조 구현에서 각각 해당 노드를 찾아 왼쪽 자식, 오른쪽 자식, 부모, 형제를 출력하도록 구현하였다.

배열 구현에서는 노드의 인덱스를 이용하여 관계를 바로 계산할 수 있다.

```c
parent = index / 2;
```

형제 노드 역시 노드의 인덱스가 짝수인지 홀수인지에 따라 반대쪽 자식의 인덱스를 계산하였다.

연결 자료구조에서는 노드의 `left`, `right` 포인터를 이용하여 자식 노드를 바로 확인할 수 있다. 부모 노드는 별도의 부모 포인터를 저장하지 않았기 때문에 루트부터 탐색하여 해당 노드의 부모를 찾도록 구현하였다.

```c
static TreeNode* linkedFindParent(
    TreeNode* node,
    TreeNode* target)
{
    ...
}
```

이를 통해 두 구현 방식에서 부모·자식·형제 관계를 탐색하는 방법의 차이를 확인할 수 있도록 하였다.

## 구현 방식 비교

### 배열 기반 구현

배열 기반 이진트리는 부모와 자식의 관계를 인덱스로 표현하기 때문에 부모와 형제의 위치를 계산하기 쉽다는 특징이 있다.

```text
부모       : index / 2
왼쪽 자식  : index * 2
오른쪽 자식: index * 2 + 1
```

그러나 트리가 편향될수록 실제 노드가 없는 배열 공간이 많이 발생할 수 있다.

### 연결 자료구조 기반 구현

연결 자료구조는 각 노드에 왼쪽과 오른쪽 자식 포인터를 저장하고 필요한 노드만 동적으로 생성한다.

따라서 노드가 없는 빈 배열 공간을 별도로 확보할 필요가 없지만, 부모 포인터를 저장하지 않았기 때문에 특정 노드의 부모를 찾을 때에는 트리를 탐색해야 한다.
