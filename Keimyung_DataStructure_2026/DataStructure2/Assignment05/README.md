### 2. 포인터 연결 방식의 이진 탐색 트리 생성

각 노드는 정수 데이터와 왼쪽, 오른쪽 자식을 가리키는 포인터를 저장하도록 구성하였다.

```c
typedef struct Node {
    int data;
    struct Node* left;
    struct Node* right;
} Node;
```

배열에 저장한 100개의 정수를 발생 순서대로 하나씩 `insertBST()`에 전달하여 삽입하였으며, 삽입 과정에서 기존 노드와 비교할 때마다 비교 횟수를 누적하였다.

```c
Node* insertBST(Node* root, int value, long* comparisons) {
    if (root == NULL) {
        return createNode(value);
    }

    (*comparisons)++;

    if (value < root->data) {
        root->left = insertBST(root->left, value, comparisons);
    }
    else if (value > root->data) {
        root->right = insertBST(root->right, value, comparisons);
    }
    else {
        return root;
    }

    return root;
}
```

100개를 모두 삽입한 뒤 각 삽입에서 발생한 비교 횟수를 모두 더하여 **BST 생성 과정에서 발생한 총 비교 횟수**를 별도로 측정하였다.

### 3. 순차 탐색 (Sequential Search)

배열의 첫 번째 원소부터 순서대로 탐색값과 비교하며, 값을 비교할 때마다 비교 횟수를 증가시킨다.

```c
int sequentialSearch(int arr[], int n, int key, long* comparisons) {
    int i;

    *comparisons = 0;

    for (i = 0; i < n; i++) {
        (*comparisons)++;
        if (arr[i] == key) {
            return 1;
        }
    }

    return 0;
}
```

탐색에 성공하면 그 지점까지의 비교 횟수를 반환하고, 끝까지 찾지 못하면 배열 전체(100회)를 비교한 것으로 처리한다.

### 4. BST 탐색 (BST Search)

루트 노드부터 시작하여 탐색값과 현재 노드의 값을 비교한 뒤, 작으면 왼쪽, 크면 오른쪽으로 이동하며 값을 비교할 때마다 비교 횟수를 증가시킨다.

```c
int bstSearch(Node* root, int key, long* comparisons) {
    Node* cur;

    *comparisons = 0;
    cur = root;

    while (cur != NULL) {
        (*comparisons)++;
        if (key == cur->data) {
            return 1;
        }
        else if (key < cur->data) {
            cur = cur->left;
        }
        else {
            cur = cur->right;
        }
    }

    return 0;
}
```

순차 탐색과 BST 탐색 모두 "값을 실제로 비교하는 시점"에 1회씩 증가시켜 두 방법의 비교 기준을 동일하게 맞추었다.

### 6. 동적 메모리 관리

각 노드는 `malloc()`으로 생성하며 할당 실패 시 오류 메시지를 출력하고 프로그램을 종료하도록 처리하였다.

```c
newNode = (Node*)malloc(sizeof(Node));

    printf("메모리 할당에 실패했습니다.\n");
    exit(1);
}
```

프로그램 종료 전에는 `destroyBST()`를 호출하여 트리의 모든 노드를 후위 순회 방식으로 해제하였다.

```c
void destroyBST(Node* root) {
    if (root == NULL) {
        return;
    }

    destroyBST(root->left);
    destroyBST(root->right);
    free(root);
}
```

## 성능 비교 분석

### 1. 순차 탐색과 BST 탐색의 비교 횟수 차이

이번 실행에서 순차 탐색은 총 4,931회, 평균 98.62회의 비교가 발생하였고, BST 탐색은 총 429회, 평균 8.58회의 비교가 발생하였다. 평균 비교 횟수를 기준으로 BST 탐색이 순차 탐색보다 약 11.5배 적은 비교로 동일한 탐색을 수행하였다.

순차 탐색은 값을 앞에서부터 하나씩 확인하는 구조이므로 탐색에 성공하는 경우 평균적으로 n/2회, 실패하는 경우에는 항상 n회(=100회)의 비교가 필요하다. 실제로 이번 실행에서도 탐색 대상 50개 중 47개가 배열에 존재하지 않아 매번 100회의 비교가 발생하였고, 이 때문에 평균 비교 횟수(98.62회)가 n(100)에 매우 가깝게 나타났다.

반면 BST 탐색은 한 번 비교할 때마다 왼쪽 또는 오른쪽 서브트리로 절반씩 좁혀 들어가는 구조이므로, 트리가 어느 정도 균형을 이루고 있다면 평균 비교 횟수는 트리의 높이, 즉 대략 log2(n) 수준에 머무른다. n = 100일 때 log2(100) ≈ 6.64이며, 실제 측정한 평균 비교 횟수 8.58회는 이 이론값에 근접한 수준으로, 100개의 값이 무작위 순서로 삽입되어 완전히 균형 잡힌 트리보다는 약간 더 높은 높이를 갖게 되었기 때문으로 볼 수 있다.

### 2. BST 생성 비용을 고려한 분석

BST는 탐색이 빠른 대신 트리를 구성하는 과정에서도 비교가 발생한다. 이번 실행에서는 100개의 값을 삽입하는 동안 총 649회의 비교가 발생하였다.

이 생성 비용까지 포함하면 BST 쪽의 총 비교 횟수는 649(생성) + 429(탐색 50회) = 1,078회이며, 이는 순차 탐색의 총 비교 횟수 4,931회보다 여전히 훨씬 적다.

탐색 1회당 순차 탐색과 BST 탐색의 평균 비교 횟수 차이는 약 98.62 - 8.58 = 90.04회이므로, BST 생성에 든 649회의 비용은 대략 649 / 90.04 ≈ 7.2회의 탐색만 수행해도 회수(손익분기)된다. 이번 실행에서는 50회의 탐색을 수행하였으므로 생성 비용은 충분히 상쇄되고도 남으며, 탐색을 반복할수록 BST 쪽의 이득은 더욱 커진다. 즉 트리를 한 번만 만들고 탐색을 한두 번만 수행하는 경우라면 생성 비용이 부담이 될 수 있지만, 이번 과제처럼 여러 번(50회) 반복 탐색하는 상황에서는 생성 비용을 고려하더라도 BST가 순차 탐색보다 명백히 효율적이다.

### 3. 이진 탐색 트리 구조에 따른 탐색 성능 변화

이번 과제에서 BST 탐색의 평균 비교 횟수(8.58회)가 이론적인 log2(100)(≈6.64회)보다 다소 높게 나타난 이유는, 100개의 값이 정렬되지 않은 무작위 순서로 하나씩 삽입되었기 때문이다. 무작위 순서로 삽입하면 트리는 대체로 균형에 가깝게 만들어지지만 완전히 균형 잡힌 트리가 되는 것은 아니므로 일부 경로의 높이가 이론적인 최소 높이보다 더 커질 수 있다.

만약 100개의 값을 미리 정렬한 뒤 오름차순(또는 내림차순) 순서로 그대로 삽입했다면, 모든 값이 이전 노드보다 항상 크거나(또는 작거나) 하므로 각 노드가 오른쪽(또는 왼쪽) 자식만 갖는 편향 이진트리(linked list와 동일한 형태)가 만들어진다. 이 경우 트리의 높이가 n(=100)에 가까워져 BST 탐색도 순차 탐색과 마찬가지로 O(n)에 가까운 비교 횟수가 필요하게 되어, BST를 사용하는 이점이 거의 사라지게 된다.

따라서 BST 탐색이 O(log n) 수준의 성능을 내려면 삽입되는 데이터의 순서가 어느 정도 무작위여야 하며, 정렬된 순서로 데이터가 계속 들어오는 경우에는 트리가 한쪽으로 치우치지 않도록 균형을 맞추는 균형 이진 탐색 트리(AVL 트리, 레드-블랙 트리 등)를 사용해야 한다는 점을 이번 과제를 통해 확인할 수 있었다.
