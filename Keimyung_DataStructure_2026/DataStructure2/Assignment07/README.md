# [자료구조2] Assignment 07 - 2026.10.10

## 과제

정점이 **100개**인 그래프를 대상으로 **인접 행렬** 과 **인접 리스트** 의 특성과 성능을 비교하는 프로그램을 작성한다.

다음 두 종류의 그래프를 임의로 생성한다.

- **희소 그래프(Sparse Graph)** : 정점 100개, 간선 100개
- **밀집 그래프(Dense Graph)** : 정점 100개, 간선 4,000개

각각의 그래프를 인접 행렬과 인접 리스트로 표현하고, 그래프가 사용하는 **메모리 용량**과 여러 그래프 연산에서 발생하는 **비교 횟수**를 측정하여 성능 차이를 분석한다.

---

## 구현 내용

- 정점이 100개인 **무방향 단순 그래프**를 사용하며 정점 번호는 `0 ~ 99`를 사용
- 자기 자신을 연결하는 간선(Self-loop)과 중복 간선은 생성하지 않음
- 간선 생성 시 중복 여부를 확인하기 위한 임시 배열(`exists`)을 사용하며, 이 배열은 메모리 측정에서 제외
- 희소 그래프와 밀집 그래프를 각각 한 번씩 랜덤 생성하고, **동일한 간선 목록**으로 인접 행렬과 인접 리스트를 구성
- 인접 행렬은 `int matrix[100][100]`로 구현하며, 간선 `(u, v)`를 추가할 때 `matrix[u][v]`와 `matrix[v][u]`를 모두 `1`로 설정
- 인접 리스트는 `Node { int vertex; Node* next; }` 구조의 단순 연결 리스트로 구현하며, 정점마다 헤드 포인터를 하나씩 가짐
- 인접 리스트는 노드를 **리스트의 맨 앞에 삽입**하며, 간선 `(u, v)`를 추가할 때 `u`의 리스트에 `v`를, `v`의 리스트에 `u`를 각각 저장
- 그래프별로 다음 대상을 **한 번만 선택**하고, 인접 행렬과 인접 리스트에 **동일하게** 적용
  - 삽입할 간선 : 현재 그래프에 존재하지 않는 서로 다른 두 정점
  - 삭제할 간선 : 생성된 간선 중 하나
  - 연결 여부 확인 : 서로 다른 임의의 두 정점
  - 인접 정점 출력 : 임의의 정점 하나
- 실행 순서는 `그래프 구성 → 메모리 측정 → 간선 삽입 → 간선 삭제 → 연결 여부 확인 → 인접 정점 출력`

### 비교 횟수 기준

| 연산 | 인접 행렬 | 인접 리스트 |
| ---- | ---- | ---- |
| 간선 삽입 | `matrix[u][v]` 확인 1회 | `u`의 리스트를 끝까지 확인한 노드 수 (중복 여부 검사) |
| 간선 삭제 | `matrix[u][v]` 확인 1회 | `u`의 리스트에서 `v`를 찾기까지 확인한 노드 수 + `v`의 리스트에서 `u`를 찾기까지 확인한 노드 수 |
| 연결 여부 확인 | `matrix[u][v]` 확인 1회 | `u`의 리스트에서 `v`를 찾거나 끝날 때까지 확인한 노드 수 |
| 인접 정점 출력 | `matrix[u][0] ~ matrix[u][99]` 확인 100회 | `u`의 리스트에 저장된 노드 수 |

- 인접 행렬에서 값을 `0` 또는 `1`로 바꾸는 대입 연산은 비교 횟수에 포함하지 않았다.
- 인접 리스트에서 노드를 생성하고 연결하는 연산도 비교 횟수에 포함하지 않았다.

### 메모리 측정 기준

- 인접 행렬 : `sizeof(AdjacencyMatrix)` = `100 × 100 × sizeof(int)` = **40,000 Bytes**
- 인접 리스트 : `sizeof(AdjacencyList)` + `노드 수 × sizeof(Node)`
  - `sizeof(AdjacencyList)` : 헤드 포인터 100개(`8 × 100 = 800`) + 노드 개수 변수(`8`) = **808 Bytes**
  - `sizeof(Node)` : `int`(4) + 패딩(4) + 포인터(8) = **16 Bytes** (64비트 환경 기준)
  - 무방향 그래프이므로 간선 1개당 노드 2개가 저장됨
- 메모리는 그래프를 구성한 직후, 간선 삽입·삭제를 수행하기 전에 측정

## 2. 메모리 사용량

| 경우 | 자료구조 | 메모리 (Bytes) |
| ---- | ---- | -: |
| Case 1 | 희소 그래프 - 인접 행렬 | 40,000 |
| Case 2 | 희소 그래프 - 인접 리스트 | 4,008 |
| Case 3 | 밀집 그래프 - 인접 행렬 | 40,000 |
| Case 4 | 밀집 그래프 - 인접 리스트 | 128,808 |

인접 행렬은 간선의 수와 관계없이 `100 × 100` 크기의 배열을 항상 확보하므로 희소 그래프와 밀집 그래프에서 모두 **40,000 Bytes**로 같았다.

인접 리스트는 간선 수에 비례하여 노드가 생성되므로 메모리 사용량이 크게 달라졌다.

```text
희소 그래프 : 808 + (100 × 2) × 16  =   808 +   3,200 =   4,008 Bytes
밀집 그래프 : 808 + (4000 × 2) × 16 =   808 + 128,000 = 128,808 Bytes
```

실제 측정값이 위의 계산 결과와 일치하였다.

- 희소 그래프에서 인접 리스트는 인접 행렬의 약 **10%** 수준(약 9.98배 적음)의 메모리만 사용하였다.
- 밀집 그래프에서는 인접 리스트가 인접 행렬보다 약 **3.22배** 많은 메모리를 사용하였다.
- 간선 수가 40배 늘어나는 동안(100 → 4,000) 인접 리스트의 노드 수도 40배(200 → 8,000) 늘었고, 메모리는 약 32배(4,008 → 128,808) 증가하였다. 정점 수에 해당하는 기본 공간 808 Bytes는 간선 수와 무관하게 고정이기 때문이다.

이번 구현의 크기 기준으로 계산하면, 인접 리스트가 인접 행렬보다 메모리를 더 많이 쓰기 시작하는 간선 수는 다음과 같다.

```text
808 + (E × 2) × 16 > 40,000  →  E ≥ 1,225
```

즉 간선이 약 1,225개(밀도 약 24.7%) 이상이 되면 이번 구현에서는 인접 리스트의 메모리 사용량이 인접 행렬보다 커진다. 이 값은 `int` 행렬과 16바이트 노드를 사용한 이번 구현 기준이며, 행렬을 `char` 등으로 구현하거나 노드 크기가 달라지면 바뀔 수 있다.

## 3. 간선 삽입 및 삭제의 비교 횟수

| 경우 | 삽입 비교 횟수 | 삭제 비교 횟수 |
| ---- | -: | -: |
| 희소 그래프 - 인접 행렬 | 1 | 1 |
| 희소 그래프 - 인접 리스트 | 1 | 3 |
| 밀집 그래프 - 인접 행렬 | 1 | 1 |
| 밀집 그래프 - 인접 리스트 | 84 | 13 |

인접 행렬은 `matrix[u][v]` 한 칸만 확인하면 되므로 그래프의 밀도와 관계없이 삽입과 삭제 모두 **1회**였다.

인접 리스트의 삽입은 중복 간선이 없는지 확인하기 위해 `u`의 인접 리스트를 처음부터 끝까지 확인한다. 삽입할 간선은 그래프에 존재하지 않는 간선이므로 중간에 멈추지 못하고, 비교 횟수가 **`u`의 인접 노드 수(차수)** 와 같아진다. 희소 그래프에서는 1회였지만 밀집 그래프에서는 **84회**로 크게 증가하였다.

인접 리스트의 삭제는 `u`의 리스트에서 `v`를, `v`의 리스트에서 `u`를 각각 찾아 제거해야 하므로 두 리스트에서 확인한 노드 수의 합이 비교 횟수가 된다. 희소 그래프에서는 3회, 밀집 그래프에서는 13회였다. 삭제는 대상 노드를 찾으면 바로 멈추기 때문에 삽입(리스트 전체를 확인)보다 비교 횟수가 적게 나왔고, 노드가 리스트의 앞쪽에 있을수록 비교 횟수가 줄어든다.

## 4. 두 정점의 연결 여부 확인

| 경우 | 비교 횟수 |
| ---- | -: |
| 희소 그래프 - 인접 행렬 | 1 |
| 희소 그래프 - 인접 리스트 | 2 |
| 밀집 그래프 - 인접 행렬 | 1 |
| 밀집 그래프 - 인접 리스트 | 57 |

인접 행렬은 `matrix[u][v]`를 직접 확인하므로 항상 **1회**였다.

인접 리스트는 `u`의 리스트를 앞에서부터 확인하며 `v`를 찾아야 한다. 희소 그래프에서는 `u`에 연결된 노드 자체가 적어 2회만 확인하면 되었지만, 밀집 그래프에서는 `u`에 연결된 노드가 많아 **57회**를 확인하였다.

인접 리스트의 비교 횟수는 `v`가 리스트의 어느 위치에 있는지, 또는 연결되어 있지 않다면 `u`의 리스트 전체를 확인해야 하므로 `u`의 차수에 따라 달라진다. 따라서 이번 결과는 한 번 선택된 정점 쌍에 대한 값이며 실행할 때마다 달라질 수 있다.

인접 행렬은 `matrix[u][0]`부터 `matrix[u][99]`까지 한 행 전체를 확인해야 하므로, 인접 정점이 3개든 83개든 항상 **100회**였다.

인접 리스트는 `u`의 리스트에 저장된 노드만 확인하므로 비교 횟수가 인접 정점의 수와 같았다.

두 표현 방식이 출력한 인접 정점의 집합은 각 그래프에서 동일하였다. 다만 출력 순서는 달랐는데, 인접 행렬은 정점 번호의 오름차순으로 출력되고, 인접 리스트는 노드를 리스트의 맨 앞에 삽입하기 때문에 나중에 추가된 간선의 정점이 먼저 출력된다.

## 6. 희소 그래프에서의 분석

희소 그래프의 평균 차수는 2로, 정점 하나에 연결된 간선이 매우 적다.

| 항목 | 인접 행렬 | 인접 리스트 |
| ---- | -: | -: |
| 메모리 (Bytes) | 40,000 | 4,008 |
| 간선 삽입 | 1 | 1 |
| 간선 삭제 | 1 | 3 |
| 연결 여부 확인 | 1 | 2 |
| 인접 정점 출력 | 100 | 3 |

- **메모리** : 인접 행렬은 간선이 거의 없어도 `100 × 100` 칸을 모두 확보하므로 대부분의 칸이 `0`으로 낭비된다. 인접 리스트는 실제 간선에 해당하는 노드만 저장하여 약 10분의 1의 메모리만 사용하였다.
- **삽입·삭제·연결 여부 확인** : 인접 리스트의 각 정점에 연결된 노드가 적어서 비교 횟수가 인접 행렬과 거의 차이가 없었다(최대 2회 차이).
- **인접 정점 출력** : 인접 행렬은 인접 정점이 3개뿐인데도 100칸을 모두 확인하였고, 인접 리스트는 3개의 노드만 확인하였다. 희소 그래프에서 인접 리스트의 이점이 가장 크게 나타난 연산이다.

결론적으로 희소 그래프에서는 인접 리스트가 메모리와 인접 정점 탐색에서 크게 유리하고, 나머지 연산에서도 인접 행렬과 비교 횟수가 거의 같았다.

## 7. 밀집 그래프에서의 분석

밀집 그래프의 평균 차수는 80으로, 정점 하나가 대부분의 다른 정점과 연결되어 있다.

| 항목 | 인접 행렬 | 인접 리스트 |
| ---- | -: | -: |
| 메모리 (Bytes) | 40,000 | 128,808 |
| 간선 삽입 | 1 | 84 |
| 간선 삭제 | 1 | 13 |
| 연결 여부 확인 | 1 | 57 |
| 인접 정점 출력 | 100 | 83 |

- **메모리** : 인접 행렬은 희소 그래프와 같은 40,000 Bytes를 사용하였다. 인접 리스트는 간선마다 노드 2개(32 Bytes)가 필요하고 노드마다 포인터까지 저장해야 하므로 약 3.22배 많은 메모리를 사용하였다.
- **삽입·삭제·연결 여부 확인** : 인접 행렬은 모두 1회였지만, 인접 리스트는 정점당 노드가 많아 리스트를 길게 탐색해야 하므로 삽입 84회, 삭제 13회, 연결 확인 57회로 크게 증가하였다.
- **인접 정점 출력** : 인접 행렬은 100회, 인접 리스트는 83회로 차이가 17회에 그쳤다. 인접 정점이 대부분이라 인접 행렬이 확인하는 100칸 중 약 83칸이 실제 인접 정점이기 때문이다.

결론적으로 밀집 그래프에서는 인접 행렬이 메모리와 간선 관련 연산(삽입, 삭제, 연결 여부 확인) 모두에서 유리하였고, 인접 정점 출력에서만 인접 리스트가 근소하게 적은 비교 횟수를 보였다.

---

## 8. 그래프의 밀도가 성능에 미치는 영향

그래프의 밀도에 따라 두 표현 방식의 성능 변화가 다르게 나타났다.

```text
인접 행렬 : 밀도가 변해도 메모리와 모든 연산의 비교 횟수가 거의 일정
            (메모리 40,000 → 40,000 / 삽입·삭제·연결 확인 1회 / 인접 정점 출력 100회)

인접 리스트 : 밀도가 높아질수록 메모리와 연산의 비교 횟수가 함께 증가
            (메모리 4,008 → 128,808 / 삽입 1 → 84 / 연결 확인 2 → 57 / 인접 정점 출력 3 → 83)
```

인접 행렬의 비용은 정점의 수(`V = 100`)로 결정되고, 인접 리스트의 비용은 정점의 수와 간선의 수, 그리고 선택된 정점의 차수로 결정된다. 따라서 간선이 적을수록 인접 리스트가 유리하고, 간선이 많아질수록 인접 행렬과의 차이가 줄어들거나 역전된다.

---

## 9. 어떤 경우에 어떤 표현 방식이 적절한가

| 상황 | 적절한 표현 방식 | 이유 |
| ---- | ---- | ---- |
| 간선이 적은 희소 그래프 | 인접 리스트 | 간선 수에 비례하는 메모리만 사용하고, 인접 정점 탐색 시 실제 연결된 정점만 확인 |
| 간선이 많은 밀집 그래프 | 인접 행렬 | 이번 구현 기준 약 1,225개 이상의 간선부터 인접 리스트보다 메모리가 적고, 간선 확인·삽입·삭제가 항상 1회 |
| 두 정점의 연결 여부를 자주 확인하는 경우 | 인접 행렬 | `matrix[u][v]` 한 칸만 확인하면 됨 |
| 한 정점의 인접 정점을 자주 순회하는 경우 | 인접 리스트 | 연결된 정점만 확인하므로 차수가 작을수록 유리 |
| 정점의 수가 매우 많은 경우 | 인접 리스트 | 인접 행렬은 `V²`에 비례하여 메모리가 증가 |

이번 실험에서 정점의 수는 100개로 고정이었으므로 인접 행렬의 메모리는 40,000 Bytes로 일정했다. 하지만 정점의 수가 커지면 인접 행렬의 메모리는 정점 수의 제곱에 비례하여 증가하므로, 간선이 적은 대규모 그래프에서는 인접 리스트가 더 적합하다.

---

## 10. 시간 복잡도 관점

정점의 수를 `V`, 간선의 수를 `E`, 정점 `u`의 차수를 `deg(u)`라고 할 때 일반적인 복잡도는 다음과 같다.

| 항목 | 인접 행렬 | 인접 리스트 |
| ---- | ---- | ---- |
| 메모리 | O(V²) | O(V + E) |
| 간선 삽입 (중복 확인 포함) | O(1) | O(deg(u)) |
| 간선 삭제 | O(1) | O(deg(u) + deg(v)) |
| 연결 여부 확인 | O(1) | O(deg(u)) |
| 인접 정점 출력 | O(V) | O(deg(u)) |

이번 실험 결과는 위 표와 일치하였다. 인접 행렬의 연산 비교 횟수는 밀도와 관계없이 일정했고, 인접 리스트의 비교 횟수는 선택된 정점의 차수와 노드의 위치에 따라 달라져 희소 그래프에서는 작고 밀집 그래프에서는 크게 나타났다.

---

## 11. 결론

이번 실험에서는 동일한 희소 그래프(간선 100개)와 밀집 그래프(간선 4,000개)를 인접 행렬과 인접 리스트로 각각 표현하고, 메모리 사용량과 각 연산의 비교 횟수를 측정하였다.

- 메모리 사용량은 인접 행렬이 두 그래프 모두 **40,000 Bytes**, 인접 리스트가 희소 그래프에서 **4,008 Bytes**, 밀집 그래프에서 **128,808 Bytes**였다.
- 희소 그래프에서는 인접 리스트가 메모리를 약 10분의 1만 사용하였고, 인접 정점 출력도 **100회에서 3회**로 줄었으며, 삽입·삭제·연결 여부 확인의 비교 횟수는 인접 행렬과 거의 같았다.
- 밀집 그래프에서는 인접 리스트가 메모리를 약 3.22배 더 사용하였고, 삽입 **84회**, 삭제 **13회**, 연결 여부 확인 **57회**로 인접 행렬(각 1회)보다 훨씬 많은 비교가 필요하였다. 인접 정점 출력만 인접 리스트가 **83회**로 인접 행렬(100회)보다 적었다.

따라서 **간선이 적은 희소 그래프에는 인접 리스트**, **간선이 많은 밀집 그래프나 두 정점의 연결 여부를 자주 확인해야 하는 경우에는 인접 행렬**이 더 적절하다는 것을 확인하였다. 이번 실험을 통해 같은 그래프라도 **그래프의 밀도와 표현 방법에 따라 공간 사용량과 연산 성능이 달라질 수 있음**을 확인할 수 있었다.

> 인접 리스트의 비교 횟수는 선택된 정점과 노드의 위치에 따라 달라지므로 위 결과는 한 번의 실행 결과이며, 실행할 때마다 값이 달라질 수 있다. 메모리 사용량은 그래프의 간선 수가 같으면 항상 같은 값이 출력된다.
