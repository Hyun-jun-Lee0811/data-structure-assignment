# [자료구조2] Assignment 10 - 2026.10.22

## 과제

0부터 1,000,000 사이의 정수 2개(Key 1, Key 2)로 구성된 데이터를 10,000개 무작위로 생성하고, **첫 번째 키(Key 1)를 기준으로** 선택 정렬, 버블 정렬, 삽입 정렬을 구현하여 성능과 안정성을 비교한다.

- 데이터 수: 10,000개
- 데이터 구성: (Key 1, Key 2), 각각 0~1,000,000 범위의 독립적인 무작위 정수
- 정렬 기준: Key 1 오름차순 (Key 2는 정렬 기준이 아니며 데이터와 함께 이동)
- 구현 알고리즘: 선택 정렬, 버블 정렬, 조기 종료 버블 정렬, 삽입 정렬 (`>` / `>=` 두 가지)
- 측정 항목: 숫자 비교 횟수, 데이터 이동 횟수, 정렬 결과의 올바름
- 비교 대상 입력 상태: 무작위 / 이미 정렬됨 / 역순 정렬 / 일부 정렬
- 추가 검증: 조기 종료 조건의 효과, 정렬 알고리즘의 안정성(Stability)

### 1. 데이터 생성

- 하나의 데이터를 구조체로 정의하여 두 키가 항상 함께 이동하도록 구현

```c
typedef struct {
    int key1;   
    int key2;   
    int order;  
} Data;
```

- `key1`, `key2`는 `randomKey()`로 각각 독립적으로 생성하여 서로 다른 데이터에서 같은 키가 나오는 것을 허용
- `rand()`의 최댓값(`RAND_MAX`)이 Visual Studio에서는 32,767로 작기 때문에, `rand()`를 두 번 조합한 값을 `MAX_KEY + 1`로 나눈 나머지로 0~1,000,000 범위의 정수를 생성
- `order`에는 데이터가 생성된 순서(0~9,999)를 저장하여 안정성 검증에만 사용하고 정렬 기준에는 포함하지 않음

### 2. 정렬 알고리즘

| 알고리즘 | 구현 방식 |
|---|---|
| 선택 정렬 | 정렬되지 않은 부분에서 `key1`이 가장 작은 데이터를 찾아 현재 위치의 데이터와 교환. 최솟값 위치가 현재 위치와 같으면 교환하지 않음 |
| 버블 정렬 | 인접한 두 데이터의 `key1`을 비교하여 `a[j].key1 > a[j+1].key1`이면 교환. 정해진 `n-1`번의 순회를 모두 수행 |
| 조기 종료 버블 정렬 | 일반 버블 정렬과 동일하되, 한 순회 동안 교환이 한 번도 없으면 정렬 완료로 판단하여 종료 |
| 삽입 정렬 (Case A) | `current`를 임시 저장한 뒤 `a[j].key1 > current.key1`인 동안 한 칸씩 뒤로 이동, 최종 위치에 삽입 |
| 삽입 정렬 (Case B) | Case A와 동일하되 이동 조건이 `a[j].key1 >= current.key1` |

라이브러리 정렬 함수는 정렬 알고리즘으로 사용하지 않았다. `qsort()`는 **정렬된 시험 입력을 만들기 위한 사전 준비**에만 사용하였으며 이 과정은 비교·이동 횟수에 포함되지 않는다.

### 3. 비교 횟수 및 데이터 이동 횟수 측정

- **비교 횟수**: 정렬 순서를 결정하기 위해 두 데이터의 `key1`을 비교할 때마다 전역 변수 `comparisons`를 1 증가. 반복문 인덱스·종료 조건 비교와 `key2` 비교는 포함하지 않음
- **데이터 이동 횟수**: 데이터 하나를 통째로 복사·대입할 때마다 전역 변수 `movements`를 1 증가
  - 교환(`swapData`): `temp = *x`, `*x = *y`, `*y = temp` → 이동 3회
  - 삽입 정렬: `current = a[i]`(1회) + 한 칸 이동 `a[j+1] = a[j]`(이동할 때마다 1회) + 최종 위치 대입 `a[j+1] = current`(1회, 제자리여도 계산)
- 정렬 실험 전의 원본 복사(`memcpy`), 데이터 생성, 사전 정렬, 정렬 결과 검증(`isSorted`)은 카운터에 포함하지 않음. `runSort()`에서 복사를 마친 뒤 카운터를 0으로 초기화하고 정렬을 호출

### 4. 무작위 데이터 100회 반복 실험

`runRandomExperiment()`에서 다음 과정을 100회 반복하였다.

1. 새로운 무작위 데이터 10,000개 생성 (`original`)
2. 같은 `original`의 복사본을 선택 / 버블 / 조기 종료 버블 / 삽입 정렬에 각각 제공 (알고리즘마다 다른 난수를 쓰지 않음)
3. 각 정렬의 비교 횟수와 이동 횟수를 누적
4. 정렬 결과가 `key1` 오름차순인지 `isSorted()`로 확인

100회 후 총 비교 횟수, 평균 비교 횟수, 평균 이동 횟수를 출력하였다.

### 5. 입력 상태별 실험

무작위 데이터 1벌(`randomData`)에서 세 가지 입력 상태를 모두 만들어 같은 입력을 모든 정렬에 제공하였다.

| 입력 상태 | 생성 방법 |
|---|---|
| 이미 정렬된 데이터 | `qsort()`로 (`key1`, `order`) 기준 사전 정렬 |
| 역순 정렬 데이터 | 정렬된 데이터를 뒤에서부터 복사하여 뒤집음 |
| 일부 정렬된 데이터 | 정렬된 데이터에서 임의의 두 위치를 `n / 20 = 500`번 무작위로 교환 |

#### 부분 정렬 데이터 생성 방법 및 인공지능 활용

- 부분 정렬 데이터를 만드는 방법을 인공지능(Claude)에게 질문하여 ① 정렬된 데이터의 일부 원소를 무작위로 교환, ② 일정 구간만 섞기, ③ 정렬된 데이터에 소수의 무작위 교란 추가 등의 방법을 안내받았다.
- 이 중 **정렬된 데이터에서 임의의 두 위치를 500번 교환하는 방법**을 선택하였다.
- 교환 한 번에 최대 2개의 원소가 제자리에서 벗어나므로 **최대 1,000개(전체의 약 10%)** 의 원소가 흐트러지고, 나머지 약 90%는 정렬된 위치를 유지한다. (같은 위치가 중복 선택되거나 `p == q`인 경우도 있으므로 실제 흐트러진 원소는 이보다 약간 적을 수 있다.)
- 사전 정렬과 교환 연산은 시험 입력 준비 과정이므로 비교·이동 횟수에 포함하지 않았다.

### 6. 안정성 검증

- `runStabilityTest()`에서 **`key1`이 중복되는 별도의 시험 데이터**를 사용: 데이터 1,000개, `key1 = rand() % 50`(0~49, 한 키당 평균 약 20개 중복), `key2`는 무작위, `order`는 0~999
- 선택 / 버블 / 삽입(`>`) / 삽입(`>=`) 정렬에 같은 시험 데이터의 복사본을 각각 제공하여 정렬
- 정렬 후 `isSorted()`로 `key1` 오름차순이 맞는지 먼저 확인하고, `isStable()`로 안정성을 판정
  - `isStable()`: 정렬 후 인접한 두 데이터의 `key1`이 같은데 앞 데이터의 `order`가 뒤 데이터의 `order`보다 크면(= 원래 순서가 뒤바뀜) 불안정으로 판정

## 결과 분석

### 1. 무작위 데이터 100회 실험 분석

- **선택 정렬**: 입력과 관계없이 비교 횟수가 항상 `n(n-1)/2 = 49,995,000`회이므로 100회 총합이 정확히 4,999,500,000회이다. 평균 이동 횟수는 29,969.94회로 매우 적은데, 한 번 교환할 때 이동이 3회이므로 정렬 한 번에 약 9,990번만 교환한 셈이다 (29,969.94 ÷ 3 ≈ 9,989.98).
- **버블 정렬**: 비교 횟수는 선택 정렬과 같지만 평균 이동 횟수가 75,074,796.36회로 가장 많다. 인접한 데이터를 교환할 때마다 3회 이동이 발생하고, 교환 횟수는 입력의 역전 쌍(앞 데이터의 `key1`이 뒤 데이터보다 큰 쌍) 수와 같기 때문이다. 평균 교환 횟수는 75,074,796.36 ÷ 3 ≈ 25,024,932회로, 무작위 배열의 역전 쌍 기댓값 `n(n-1)/4 = 24,997,500`에 가깝다.
- **삽입 정렬**: 평균 비교 횟수가 25,034,922.39회로 선택·버블 정렬(49,995,000회)의 약 절반(50.1%)이다. 정렬된 앞부분을 평균적으로 절반 정도만 비교하고 삽입 위치를 찾으면 멈추기 때문이다. 이동 횟수 25,044,930.12회는 `역전 쌍 수 + 2(n-1)`로 설명된다. 위에서 구한 평균 역전 쌍 25,024,932.12에 `2 × 9,999 = 19,998`을 더하면 정확히 25,044,930.12회가 되어, 버블 정렬 이동 횟수로 역산한 값과 일치한다.

### 2. 일반 버블 정렬과 조기 종료 버블 정렬 비교

| 항목 | 일반 버블 정렬 | 조기 종료 버블 정렬 |
|---|---:|---:|
| 100회 총 비교 횟수 | 4,999,500,000 | 4,998,613,610 |
| 평균 비교 횟수 | 49,995,000.00 | 49,986,136.10 |
| 평균 이동 횟수 | 75,074,796.36 | 75,074,796.36 |

- 100회 총 비교 횟수의 차이는 4,999,500,000 − 4,998,613,610 = **886,390회**, 한 번당 평균 약 **8,864회**(전체의 약 0.018%)가 줄었다.
- 이동 횟수는 두 방식이 완전히 같다. 조기 종료는 교환이 없는 순회를 생략할 뿐 교환 자체는 바꾸지 않기 때문이다.
- 효과가 거의 없는 이유: 무작위 데이터에서는 작은 값이 한 순회에 한 칸씩만 왼쪽으로 이동하므로 거의 마지막 순회까지 교환이 발생한다. 줄어든 약 8,864회는 길이가 매우 짧은 마지막 약 133번의 순회(1 + 2 + … + 133 ≈ 8,900)에 해당하며, 전체 9,999번의 순회 중 약 1.3%만 생략된 것이다. 따라서 **무작위 데이터에서 조기 종료의 효과는 미미하다.**

### 3. 이미 정렬된 데이터

- 선택 정렬과 일반 버블 정렬은 이미 정렬된 입력에서도 49,995,000회를 그대로 비교한다. 입력 상태와 무관하게 정해진 횟수만큼 반복하는 구조이기 때문이다. 다만 교환이 필요 없으므로 이동은 0회이다. 선택 정렬은 최솟값 위치가 현재 위치와 같아 교환을 건너뛰고, 버블 정렬은 `>` 조건이 한 번도 참이 되지 않는다.
- 조기 종료 버블 정렬은 첫 순회에서 교환이 없음을 확인하고 종료하므로 비교가 `n-1 = 9,999`회로 줄었다. 일반 버블 정렬(49,995,000회)의 약 **1/5,000** 수준으로, 조기 종료의 효과가 가장 크게 나타나는 경우이다.
- 삽입 정렬은 각 데이터를 바로 앞 데이터와 한 번만 비교하면 멈추므로 비교가 9,999회이다. 한 칸씩 뒤로 미는 이동은 없고, 데이터마다 `current` 임시 저장 1회와 최종 위치 대입 1회만 발생하여 이동은 `2(n-1) = 19,998`회이다.

### 4. 역순으로 정렬된 데이터

- 모든 쌍이 뒤집혀 있어 모든 알고리즘이 최악의 경우가 된다. 조기 종료 버블 정렬도 마지막 순회까지 교환이 발생하므로 비교가 49,995,000회로 일반 버블 정렬과 같고, **조기 종료의 효과가 전혀 없다.** 삽입 정렬도 매번 맨 앞까지 비교하여 49,995,000회이다.
- 이동 횟수는 알고리즘마다 크게 다르다.
  - 버블 정렬: 149,984,829회. 역전 쌍마다 교환(3회)이 발생하므로 역전 쌍은 149,984,829 ÷ 3 = 49,994,943개이다. 이는 최대치 `n(n-1)/2 = 49,995,000`보다 57개 적은데, 랜덤 키에 중복된 값이 있어 같은 키 쌍은 역전 쌍으로 세어지지 않기 때문이다.
  - 삽입 정렬: 50,014,941회. 역전 쌍마다 1회씩 이동 + `2(n-1)`이므로 49,994,943 + 19,998 = 50,014,941로 정확히 일치하며, 버블 정렬의 약 1/3이다.
  - 선택 정렬: 15,099회. 약 5,000번(= n/2)만 교환하면 되므로 이동이 가장 적다. 이상적인 5,000번 교환(15,000회)보다 조금 많은 것은 중복 키가 있어 교환 과정에서 같은 키의 데이터 순서가 어긋나는 영향으로 보인다(추정).
- 비교 횟수만 보면 네 알고리즘이 같지만, 이동까지 보면 선택 정렬 < 삽입 정렬 < 버블 정렬 순이다.

### 5. 일부 정렬된 데이터

- 정렬된 데이터에서 500번 교환하여 약 10%의 데이터만 흐트러뜨린 입력이다. 버블 정렬의 이동 횟수 9,369,561 ÷ 3 = 3,123,187개가 이 입력의 역전 쌍 수이며, 삽입 정렬 이동 횟수에서 역산한 값(3,143,185 − 19,998 = 3,123,187)과 일치한다. 이는 역순 데이터 역전 쌍(49,994,943개)의 약 6.25%이다.
- **삽입 정렬**: 비교 3,133,186회, 이동 3,143,185회로 무작위 데이터(비교 25,034,922회, 이동 25,044,930회)의 약 12.5% 수준으로 크게 줄었다. 삽입 정렬의 이동 횟수가 역전 쌍 수에 비례하기 때문이며, 비교 횟수도 `역전 쌍 + (n-1) = 3,123,187 + 9,999 = 3,133,186`으로 정확히 일치한다.
- **버블 정렬**: 이동은 역전 쌍에 비례해 9,369,561회로 줄었지만, 비교는 일반 버블 정렬이 49,995,000회, 조기 종료 버블 정렬이 49,857,974회로 **137,026회(약 0.27%)만 감소**했다. 정렬된 위치에서 멀리 떨어진 곳으로 교환된 작은 데이터는 한 순회에 한 칸씩만 왼쪽으로 이동하므로, 교환이 없는 순회가 나올 때까지 거의 모든 순회가 필요하기 때문이다. 줄어든 137,026회를 순회 수로 환산하면 약 523번이고, 전체 9,999번 중 약 9,476번의 순회가 실제로 수행된 셈이다.
- **선택 정렬**: 비교는 49,995,000회로 변하지 않고, 이동은 1,512회(약 504번 교환)로 매우 적다. 제자리에서 벗어난 데이터 수만큼만 교환하기 때문이다.

### 6. 입력 상태가 각 알고리즘의 성능에 미치는 영향

| 알고리즘 | 비교 횟수 | 이동 횟수 | 특징 |
|---|---|---|---|
| 선택 정렬 | 입력과 무관하게 항상 49,995,000 | 항상 매우 적음 (0 ~ 약 15,000) | 입력 상태를 활용하지 못하지만 이동 비용이 필요 최소 |
| 버블 정렬 | 입력과 무관하게 항상 49,995,000 | 입력에 크게 좌우됨 (0 ~ 약 1.5억) | 어떤 경우에도 가장 비효율적 |
| 조기 종료 버블 정렬 | 입력에 민감 (9,999 ~ 49,995,000) | 일반 버블 정렬과 동일 | 이미 정렬된 경우 크게 개선되나, 역순·무작위·넓게 흐트러진 경우 효과 거의 없음 |
| 삽입 정렬 | 입력에 매우 민감 (9,999 ~ 49,995,000) | 입력에 민감 (19,998 ~ 약 5,000만) | 정렬에 가까울수록 급격히 빨라지고 역순에서 최악 |

성능 차이의 원인은 다음과 같이 정리할 수 있다.

- 선택 정렬은 최솟값을 찾기 위해 남은 구간을 **항상 전부 비교**하므로 입력 상태를 활용하지 못한다. 대신 교환이 정렬당 최대 `n-1`번이라 이동이 적다.
- 버블 정렬은 인접 교환 한 번이 역전 쌍을 정확히 하나만 제거하므로, 역전 쌍이 많을수록 교환(= 이동 3회)이 폭증한다.
- 삽입 정렬은 이미 정렬된 앞부분에서 **조건이 거짓이 되면 즉시 멈출 수 있어**, 비교와 이동이 역전 쌍 수에 비례한다. 그래서 데이터가 정렬에 가까울수록 유리하다.
- 조기 종료 조건의 이득은 입력이 "얼마나 많이" 흐트러졌는지보다 "얼마나 멀리" 흐트러졌는지에 좌우된다. 부분 정렬 데이터에서도 멀리 교환된 원소가 있어 거의 이득이 없었다.

### 7. 안정성 검증 결과 분석

**검증 방법과 입력 데이터**

- `key1`이 0~49 사이인 데이터 1,000개를 생성하였다 (한 `key1`당 평균 약 20개 중복). `key2`는 무작위 값이고, `order`에 원래 입력 순서(0~999)를 저장하였다.
- 같은 데이터의 복사본을 네 가지 정렬에 각각 제공하여 정렬한 뒤, `key1`이 같은 인접 데이터에서 `order`가 증가하는 순서를 유지하는지 `isStable()`로 검사하였다. 정렬 오류가 있으면 `Sort Error`가 출력되도록 하였는데 모든 경우에 정렬은 정상이었다.

**실제 결과**

| 알고리즘 | 결과 |
|---|---|
| 선택 정렬 | Unstable |
| 버블 정렬 | Stable |
| 삽입 정렬 (`>`) | Stable |
| 삽입 정렬 (`>=`) | Unstable |

(프로그램은 위반 개수는 출력하지 않고 안정 / 불안정 판정만 출력하므로, 아래 원인 설명은 과제 예시 데이터를 손으로 추적한 결과를 이용하였다.)

**원인 설명 – 과제 예시 데이터로 손으로 추적**

원래 데이터를 `(Key1, Key2)#원래순서`로 쓰면 `(527,100)#0, (527,200)#1, (125,300)#2, (892,400)#3` 이다.

- **선택 정렬 (불안정)**: `i = 0`에서 최솟값 `(125,300)#2`를 현재 위치와 교환하면 `(527,100)#0`이 맨 뒤쪽으로 가서 `(527,200)#1` 뒤에 놓인다. 결과는 `(125,300)#2, (527,200)#1, (527,100)#0, (892,400)#3`으로 527의 순서가 뒤바뀐다. 멀리 떨어진 위치와 교환하면서 중간에 있던 같은 키 데이터를 건너뛰기 때문이다. 실제 실험에서 `Unstable`로 확인되었다.
- **버블 정렬 (안정)**: 인접한 두 데이터만 비교하며 `>` 조건에서만 교환하므로, 키가 같은 데이터는 서로 교환되지 않아 서로를 추월하지 못한다. 따라서 같은 키의 상대 순서가 유지되어 `Stable`로 확인되었다.
- **삽입 정렬 (`>`, 안정)**: 같은 키를 만나면 이동 조건이 거짓이 되어 멈추므로 `current`가 같은 키 데이터들의 **뒤**에 삽입된다. 원래 순서가 유지되어 `Stable`이다.
- **삽입 정렬 (`>=`, 불안정)**: 같은 키도 뒤로 밀어내고 더 앞으로 가서 삽입되므로 `current`가 같은 키 데이터들의 **앞**에 놓인다. 예시에서 `i = 1`일 때 `(527,200)#1`이 `(527,100)#0`을 밀어내고 앞에 삽입되어 순서가 뒤바뀐다. 실제 실험에서도 `Unstable`이었다.

**삽입 정렬에서 `>`와 `>=` 사용에 따른 차이**

| 항목 | Case A (`>`) | Case B (`>=`) |
|---|---|---|
| 같은 키를 만났을 때 | 이동하지 않고 멈춤 | 이동시키고 계속 진행 |
| 같은 키 데이터의 순서 | 유지됨 | 뒤바뀜 |
| 정렬 결과(`key1` 오름차순) | 정상 | 정상 |
| 안정성 | Stable | Unstable |

두 방식 모두 `key1` 기준으로는 올바르게 정렬되지만, `>=`는 같은 키의 데이터를 불필요하게 이동시키므로 안정성을 잃고 이동 횟수도 더 많아진다 (이번 실행에서는 `>=`의 비교·이동 횟수를 따로 측정하지 않았다). 같은 키가 있는 데이터에서는 `>`를 사용하는 것이 안정성과 효율 모두에서 유리하다.

## 결론

이번 과제에서는 10,000개의 두 키 데이터를 생성하고 선택·버블·조기 종료 버블·삽입 정렬을 구현하여 비교 횟수, 데이터 이동 횟수, 안정성을 측정하였다.

- 선택 정렬과 일반 버블 정렬의 비교 횟수는 입력과 무관하게 항상 `n(n-1)/2 = 49,995,000`회이고, 삽입 정렬은 입력의 역전 쌍 수에 비례하여 무작위 데이터에서는 약 절반, 이미 정렬된 데이터에서는 9,999회까지 줄었다.
- 이동 횟수는 선택 정렬이 가장 적고, 버블 정렬은 `3 × 역전 쌍`, 삽입 정렬은 `역전 쌍 + 2(n-1)`로 나타나 입력이 뒤섞일수록 버블 정렬이 가장 불리했다.
- 조기 종료 조건은 이미 정렬된 데이터에서 비교 횟수를 49,995,000회에서 9,999회로 줄였지만, 무작위·역순·넓게 흐트러진 부분 정렬 데이터에서는 0.02~0.3% 정도만 줄여 효과가 거의 없었다.
- 안정성 검증에서 버블 정렬과 삽입 정렬(`>`)은 안정, 선택 정렬과 삽입 정렬(`>=`)은 불안정으로 확인되었다. 불안정한 이유는 각각 멀리 떨어진 위치와의 교환, 그리고 같은 키까지 밀어내는 비교 연산자 때문이다.
- 모든 실험에서 정렬 결과가 `key1` 기준 오름차순임을 확인하였고, 프로그램은 종료 코드 0으로 정상 종료되었다.

이를 통해 입력 데이터의 초기 정렬 상태, 조기 종료 조건, 비교 연산자의 선택이 정렬 알고리즘의 성능과 안정성에 직접 영향을 준다는 것을 확인하였다.
