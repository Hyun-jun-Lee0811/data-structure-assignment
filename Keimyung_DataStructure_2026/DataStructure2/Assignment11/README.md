## 과제

무작위 정수 데이터에 대해 **삽입 정렬**과 **쉘 정렬**을 수행하고, 정렬 과정에서 발생하는 **숫자 비교 횟수**를 측정하여 성능을 분석한다. 쉘 정렬은 간격(Gap)을 정하는 두 가지 방법(Shell 기본 간격, Knuth 간격)을 적용하여 간격 수열에 따른 성능 차이를 비교한다.

- 데이터 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 데이터 구성: `rand()`로 생성한 무작위 정수
- 정렬 기준: 오름차순
- 구현 알고리즘: 삽입 정렬, 쉘 정렬 (Shell 기본 간격), 쉘 정렬 (Knuth 간격)
- 측정 항목: 데이터 값 사이의 비교 횟수, 정렬 결과의 올바름
- 추가 분석: 데이터 크기 증가에 따른 비교 횟수 변화, 간격 수열이 성능에 미치는 영향

## 구현 내용

### 1. 데이터 생성

- 데이터 크기 `n`마다 원본 배열(`orig`)을 `rand()`로 한 번만 생성
- 정렬 알고리즘마다 `orig`를 작업용 배열(`work`)에 복사하여 사용하므로, **세 알고리즘이 항상 동일한 데이터**를 정렬
- 데이터 생성과 배열 복사는 비교 횟수 측정에서 제외 (복사를 마친 뒤 `cnt = 0`으로 초기화하고 정렬을 호출)

### 2. 정렬 알고리즘

| 알고리즘 | 구현 방식 |
|---|---|
| 삽입 정렬 | `key = a[i]`를 저장한 뒤 앞쪽(`j = i - 1`)부터 `a[j] > key`인 동안 한 칸씩 뒤로 이동하고, 멈춘 위치에 `key`를 삽입 |
| 쉘 정렬 (Original) | 간격을 `h = n/2`로 시작하여 매 단계 `h /= 2`로 줄이고, 각 간격마다 간격 `h`를 이용한 삽입 정렬 수행. 마지막 간격은 1 |
| 쉘 정렬 (Knuth) | `h(1) = 1`, `h(k+1) = 3h(k) + 1` (1, 4, 13, 40, 121, 364, 1093, …)로 `n`보다 작은 가장 큰 간격을 구한 뒤, `h = (h - 1) / 3`으로 역순 적용. 마지막 간격은 1 |

- 쉘 정렬은 간격 `h`에서 `h`칸 떨어진 원소끼리 삽입 정렬을 하는 구조이며, `h = 1`이면 일반 삽입 정렬과 동일
- 라이브러리 정렬 함수(`qsort` 등)는 사용하지 않음

### 3. 비교 횟수 측정

- **비교 횟수**: 데이터 값끼리 비교하는 `a[j] > key`를 수행할 때마다 전역 변수 `cnt`를 1 증가. 비교 결과(참/거짓)와 관계없이 1회로 계산
- 반복문의 인덱스·종료 조건 검사(`i < n`, `j >= 0` 등)는 포함하지 않음
- 원본 데이터 생성, 배열 복사, 정렬 결과 검증(`is_sorted`)은 카운터에 포함하지 않음
- 정렬이 끝나면 `is_sorted()`로 오름차순 여부를 확인하고, 실패하면 오류 메시지를 출력하고 종료

## 결과 분석

### 1. 데이터 크기 증가에 따른 비교 횟수 변화

- **삽입 정렬**: n이 2배가 될 때마다 비교 횟수가 약 **4배**(3.95 ~ 4.04배)로 늘어난다. 즉 비교 횟수가 `n²`에 비례한다. 실제로 `n²/4`와 비교하면 모든 크기에서 0.995 ~ 1.011배로 거의 일치한다. 무작위 배열에서 삽입 정렬의 비교 횟수는 대략 `역전 쌍 수 + (n-1)`이고 무작위 배열의 역전 쌍 기댓값이 `n(n-1)/4`이므로 이 결과는 이론과 맞는다.
- **쉘 정렬 (Original)**: n이 2배가 될 때 비교 횟수는 약 **2.3 ~ 2.5배**로 늘어난다. 삽입 정렬의 4배보다 훨씬 완만하며, 2.35배를 지수로 환산하면 `n^1.2` 정도에 해당한다.
- **쉘 정렬 (Knuth)**: 2배가 될 때 **2.2 ~ 2.6배**로 늘어나 Original과 비슷하게 완만한 증가를 보인다.
- n이 16,000에서 20,000으로 1.25배가 될 때 삽입 정렬은 1.55배(`1.25² = 1.5625`에 가까움), 쉘 정렬은 1.24 ~ 1.28배로 증가해, **n이 커질수록 삽입 정렬과의 차이가 점점 벌어진다.**

### 2. 삽입 정렬과 쉘 정렬의 성능 차이

- n = 1,000에서 쉘 정렬은 삽입 정렬 대비 약 17 ~ 18배 적게 비교하고, n = 20,000에서는 약 **166 ~ 189배** 적게 비교한다. 즉 n이 커질수록 쉘 정렬의 이득이 급격히 커진다.
- 원인은 **원소가 한 번에 이동하는 거리**에 있다. 삽입 정렬은 원소를 한 칸씩만 옮기므로 제자리에서 멀리 떨어진 원소는 그 거리만큼 비교가 필요하고, 전체 비교 횟수가 역전 쌍 수(약 `n²/4`)와 같아진다. 반면 쉘 정렬은 큰 간격으로 먼저 멀리 있는 원소들을 한 번에 제자리 근처로 보내므로, 하나의 비교로 여러 개의 역전 쌍이 해소된다.
- 큰 간격 단계를 거치고 나면 배열이 어느 정도 정렬된 상태가 된다. 마지막 `h = 1` 단계(일반 삽입 정렬)는 거의 정렬된 입력에서 수행되므로, 삽입 정렬이 정렬에 가까운 입력에서 매우 빠르다는 성질(비교 횟수가 역전 쌍 수에 비례)을 그대로 활용할 수 있다. 쉘 정렬의 이득은 결국 "삽입 정렬이 거의 정렬된 데이터에 강하다"는 성질을 앞 단계에서 미리 만들어 주는 데서 나온다.

### 3. 쉘 정렬의 기본 간격과 Knuth 간격의 성능 차이

- 이번 실험에서는 **모든 데이터 크기에서 Knuth 간격이 Original보다 비교 횟수가 적었다.** 감소율은 n = 1,000에서 5.0%, 2,000에서 14.7%, 4,000에서 15.1%, 8,000에서 8.1%, 16,000에서 15.8%, 20,000에서 12.5%였다.
- 다만 삽입 정렬과의 차이(수십 ~ 170배)에 비하면 두 간격 수열의 차이(5.0 ~ 15.8%)는 작다. **간격 수열의 선택보다 "쉘 정렬 구조 자체를 사용하는 것"의 영향이 훨씬 크다.**
- 감소율이 데이터 크기에 따라 단조롭게 변하지 않고 들쭉날쭉하다(5.0% → 14.7% → 15.1% → 8.1% → 15.8% → 12.5%). 이번 실험은 크기당 1회 실행이고 무작위 데이터의 영향을 받으므로, 이 변동만으로 `n`에 따른 경향을 단정하기는 어렵다. 다만 **어느 크기에서도 Original이 Knuth보다 적게 비교한 경우는 없었다**는 점은 일관되게 나타났다.
- 간격의 개수도 차이가 난다. n = 20,000에서 Original은 14단계, Knuth는 9단계를 거친다. Knuth는 간격이 약 3배씩 줄어 단계 수가 적고, 각 단계에서 `n`개 안팎의 원소를 한 번씩 훑는 비용이 단계 수에 비례해 들어가므로 불필요한 단계가 적다.

### 4. 간격 수열이 쉘 정렬의 성능에 영향을 미치는 이유

> 아래 내용 중 간격의 수학적 성질에 대한 설명은 쉘 정렬에 대해 알려진 일반적 성질이며, 이번 실험은 위 3번의 측정 결과(모든 n에서 Knuth가 적음)로 이를 간접 확인한 것이다.

- **간격이 서로소에 가까운지 여부**: 간격 `h`로 정렬하면 `i mod h`가 같은 원소끼리만 서로 비교된다. Original(`n/2, n/4, …`)은 앞쪽 간격들이 서로 배수 관계(예: n = 16,000에서 8000, 4000, 2000, 1000, 500, 250, 125는 모두 125의 배수)여서, 이미 정렬한 간격의 원소 묶음 사이를 다음 단계가 새로 섞어 주지 못한다. 배수 관계가 있으면 서로 다른 묶음에 있는 원소끼리는 간격이 줄어도 한참 뒤에야 비교되고, 그만큼 나중 단계의 삽입 정렬이 해야 할 일이 남는다. Knuth 수열(1, 4, 13, 40, 121, …)은 `3h + 1` 꼴로 인접한 간격이 서로소에 가까워 단계마다 원소 묶음이 새로 섞이므로, 각 단계가 앞 단계의 작업을 더 효과적으로 이어받는다.
- **간격 감소 비율**: 간격을 너무 천천히 줄이면(Original은 1/2씩) 단계 수가 늘어 매 단계 `n`개 안팎의 원소를 훑는 비용이 쌓인다. 간격을 약 1/3씩 줄이는 Knuth는 단계 수가 적으면서도 각 단계의 입력이 이미 어느 정도 정렬된 상태를 유지한다. 이번 실험에서 n = 20,000일 때 단계 수가 14개 대 9개로 차이가 난 것이 이를 보여 준다.
- **마지막 단계(`h = 1`)의 부담**: 쉘 정렬의 총 비용은 앞 단계가 배열을 얼마나 정렬해 두느냐에 달려 있다. 앞 단계가 충분히 정렬해 두지 못하면 마지막 `h = 1` 단계가 삽입 정렬에 가까운 비용을 치르게 된다. 간격 수열이 좋다는 것은 앞 단계가 역전 쌍을 효율적으로 줄여 마지막 단계 부담을 작게 만든다는 뜻이다.
- 일반적으로 알려진 이론상 최악 복잡도는 Shell 원래 수열이 `O(n²)`, Knuth 수열이 `O(n^1.5)`이다. 이번 무작위 데이터 실험에서는 두 수열 모두 `n^1.2` 정도의 완만한 증가를 보여 최악 복잡도 차이가 뚜렷이 드러나지는 않았고, 실제 차이는 5.0 ~ 15.8% 수준이었다. 무작위 입력은 최악 입력이 아니므로 이론상 차이만큼 벌어지지 않은 것으로 볼 수 있다.

## 결론

이번 과제에서는 무작위 데이터 n = 1,000 ~ 20,000에 대해 삽입 정렬과 두 가지 간격 수열의 쉘 정렬의 비교 횟수를 측정하고 분석하였다.

- 삽입 정렬은 n이 2배가 될 때 비교 횟수가 약 4배로 늘어 `n²`에 비례하였고, n = 20,000에서 약 1억 회(99,677,100회)를 비교하였다.
- 쉘 정렬은 n이 2배가 될 때 약 2.2 ~ 2.6배로만 늘어났으며, n = 20,000에서 삽입 정렬의 약 1/166 ~ 1/189 수준(Original 602,135회, Knuth 526,573회)의 비교만 수행하였다. n이 커질수록 쉘 정렬의 이득이 더 커졌다.
- 쉘 정렬의 성능 향상은 큰 간격 단계에서 원소를 한 번에 멀리 이동시켜 마지막 `h = 1` 단계를 거의 정렬된 입력에서 수행하게 만들기 때문이다.
- Knuth 간격은 모든 데이터 크기에서 Original 간격보다 비교 횟수가 5.0 ~ 15.8% 적었다. 이는 간격이 서로소에 가까워 단계마다 원소 묶음이 새로 섞이고, 간격이 약 1/3씩 줄어 단계 수가 적기 때문으로 해석된다. 다만 크기당 1회 실험이므로 감소율의 크기 변화는 추가 반복 실험이 필요하다.
- 모든 실험에서 정렬 결과가 오름차순임을 확인하였다.

이를 통해 정렬 알고리즘의 비교 횟수 증가율은 알고리즘의 구조(한 칸씩 이동 vs. 간격을 둔 이동)에 의해 가장 크게 결정되며, 같은 구조 안에서도 간격 수열의 선택이 추가적인 성능 차이를 만든다는 것을 확인하였다.
