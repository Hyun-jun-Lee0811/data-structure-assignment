# [자료구조2] Assignment 12 - 퀵 정렬의 피벗 선택에 따른 성능 비교

## 과제

무작위 정수 데이터에 대해 **퀵 정렬(Quick Sort)**을 수행하고, 피벗(Pivot)을 선택하는 방법에 따른 성능 차이를 비교한다. 세 가지 피벗 선택 방법(첫 번째 원소, 무작위 원소, 세 원소의 중앙값)을 적용하여 정렬 과정에서 발생하는 **숫자 비교 횟수**를 측정하고 성능을 분석한다.

- 데이터 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 데이터 구성: `rand()`로 생성한 무작위 정수
- 정렬 기준: 오름차순
- 구현 알고리즘: 퀵 정렬 (First Element), 퀵 정렬 (Random Pivot), 퀵 정렬 (Median-of-Three)
- 측정 항목: 데이터 값 사이의 비교 횟수, 정렬 결과의 올바름
- 추가 분석: 데이터 크기 증가에 따른 비교 횟수 변화, 피벗 선택 방법이 분할 결과와 성능에 미치는 영향
- 보너스: 재귀적 퀵 정렬과 반복적 퀵 정렬의 실행시간 비교

## 구현 내용

### 1. 데이터 생성

- 데이터 크기 `n`마다 원본 배열(`original`)을 `rand()`를 사용하여 한 번만 생성
- 각 정렬 알고리즘마다 원본 배열을 작업용 배열(`work`)에 복사하여 사용하므로, **세 가지 피벗 선택 방법이 항상 동일한 데이터**를 정렬
- 데이터 생성과 배열 복사는 비교 횟수 측정에서 제외
- `srand((unsigned int)time(NULL))`를 사용하여 실행할 때마다 다른 무작위 데이터 생성

### 2. 정렬 알고리즘

| 알고리즘 | 구현 방식 |
|---|---|
| 퀵 정렬 (First Element) | 현재 정렬 구간의 첫 번째 원소를 피벗으로 선택 |
| 퀵 정렬 (Random Pivot) | 현재 정렬 구간에서 무작위 위치의 원소를 피벗으로 선택 |
| 퀵 정렬 (Median-of-Three) | 첫 번째, 가운데, 마지막 원소 중 중앙값을 피벗으로 선택 |

- **First Element:** `low` 위치의 원소를 피벗으로 사용
- **Random Pivot:** `low + rand() % (high - low + 1)`을 통해 현재 정렬 구간에서 무작위 위치를 선택
- **Median-of-Three:** 첫 번째, 가운데, 마지막 원소의 값을 비교하여 크기순으로 중앙에 위치하는 값을 피벗으로 선택
- 세 가지 방법은 피벗을 선택하는 부분만 다르게 구현하고, 나머지 분할 알고리즘(`partition`)은 동일하게 유지
- 피벗을 선택한 후 해당 원소를 구간의 마지막 위치로 이동시키고, 피벗 이하의 값은 왼쪽, 피벗보다 큰 값은 오른쪽으로 분할
- 분할이 끝나면 피벗을 최종 위치에 배치하고, 왼쪽과 오른쪽 구간에 대해 재귀적으로 정렬 수행
- 라이브러리 정렬 함수(`qsort` 등)는 사용하지 않음

### 3. 비교 횟수 측정

- **비교 횟수:** 분할 과정에서 `arr[j] <= pivot`을 수행할 때마다 전역 변수 `comparisons`를 1 증가
- 비교 결과가 참인지 거짓인지와 관계없이 데이터 값 비교 1회를 계산
- Median-of-Three에서 중앙값을 결정하기 위해 발생하는 데이터 값 사이의 비교도 포함
- 반복문의 인덱스 및 종료 조건 검사(`j < high`, `low >= high` 등)는 포함하지 않음
- 피벗의 무작위 위치 생성과 데이터 이동 및 교환은 비교 횟수에 포함하지 않음
- 정렬 결과 검증(`isSorted`)은 비교 횟수에 포함하지 않음
- 정렬이 끝나면 `isSorted()`로 오름차순 여부를 확인

### 4. 보너스: 재귀적 퀵 정렬과 반복적 퀵 정렬

- **재귀적 퀵 정렬(Recursive):** 분할된 왼쪽과 오른쪽 구간을 함수의 재귀 호출을 통해 정렬
- **반복적 퀵 정렬(Iterative):** 재귀 호출 대신 스택(Stack)에 정렬할 구간의 시작과 끝 인덱스를 저장하고 반복문으로 정렬
- 두 방법 모두 Median-of-Three 피벗 선택 방식과 동일한 `partition()` 함수를 사용
- 데이터 크기: n = 10,000
- 동일한 원본 데이터를 사용하며, 실행시간 측정 전에 배열 복사를 완료
- `clock()`을 사용하여 정렬 실행시간을 측정하고, 300회 반복 측정한 평균값을 사용
- 데이터 생성, 배열 복사, 결과 출력 및 정렬 검증 시간은 실행시간 측정에서 제외

## 결과 분석

### 1. 데이터 크기 증가에 따른 비교 횟수 변화

- **First Element:** 데이터 크기가 2배가 될 때 비교 횟수가 약 2.16 ~ 2.36배 증가하였다. 무작위 데이터에서는 첫 번째 원소가 극단적인 피벗으로 선택될 가능성이 존재하지만, 이번 실험에서는 전체적으로 약 `n log n`에 가까운 증가 경향을 보였다.
- **Random Pivot:** 비교 횟수가 약 1.92 ~ 2.66배 증가하였다. 피벗을 무작위로 선택하기 때문에 실행마다 분할 결과가 달라질 수 있으며, 데이터 크기가 증가해도 비교 횟수가 일정한 비율로 증가하지는 않았다.
- **Median-of-Three:** 비교 횟수가 약 2.15 ~ 2.20배 증가하는 경향을 보였다. 세 원소의 중앙값을 피벗으로 선택하여 비교적 균형 잡힌 분할을 유도할 수 있기 때문에 전체적으로 안정적인 증가 추세를 나타냈다.
- n이 16,000에서 20,000으로 1.25배 증가했을 때 세 방법의 비교 횟수는 각각 1.22배, 1.28배, 1.33배 증가하였다. 데이터 크기가 증가함에 따라 비교 횟수도 증가하지만, 삽입 정렬처럼 n²에 비례하는 급격한 증가와는 차이가 있었다.

### 2. 세 가지 피벗 선택 방법의 성능 차이

- **First Element:** 현재 정렬 구간의 첫 번째 원소를 항상 피벗으로 선택한다. 구현이 간단하다는 장점이 있지만, 피벗이 최솟값이나 최댓값에 가까운 경우 분할이 한쪽으로 치우칠 수 있다. 이번 실험에서도 16,000개 데이터에서 280,855회로 가장 많은 비교 횟수를 기록하였다.
- **Random Pivot:** 현재 정렬 구간에서 무작위로 피벗을 선택하므로 특정 위치의 원소를 계속 선택하는 First Element의 단점을 줄일 수 있다. 그러나 무작위 선택이 항상 균형 잡힌 분할을 보장하지는 않는다. 실제로 2,000개 데이터에서는 27,924회로 세 방법 중 가장 많은 비교 횟수를 기록하였다.
- **Median-of-Three:** 첫 번째, 가운데, 마지막 원소 중 중앙값을 선택하여 극단적인 피벗이 선택될 가능성을 줄인다. 이번 실험에서는 6개 데이터 크기 중 4개에서 가장 적은 비교 횟수를 기록하였다. 특히 16,000개 데이터에서는 246,408회로 First Element보다 약 12.3% 적은 비교를 수행하였다.
- 전체적으로 Median-of-Three가 가장 좋은 결과를 보였지만, 1,000개와 20,000개 데이터에서는 Random Pivot이 더 적은 비교 횟수를 기록하였다. 따라서 특정 피벗 선택 방법이 모든 데이터에서 항상 가장 좋은 결과를 보이는 것은 아니며, 실제 분할 결과에 따라 성능이 달라질 수 있음을 확인하였다.

### 3. 피벗 선택 방법이 분할 결과에 영향을 미치는 이유

퀵 정렬은 피벗을 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽에 배치하는 분할 과정을 반복한다. 이때 피벗을 기준으로 양쪽 데이터가 얼마나 균형 있게 나뉘는지에 따라 전체 정렬 과정의 비교 횟수가 달라진다.

- **균형 잡힌 분할:** 피벗을 기준으로 양쪽 구간의 크기가 비슷하면 재귀적으로 처리해야 하는 데이터 크기가 빠르게 감소한다. 이 경우 평균적으로 O(n log n)의 시간 복잡도를 가진다.
- **불균형한 분할:** 피벗이 최솟값이나 최댓값에 가까우면 한쪽에는 데이터가 거의 남지 않고 다른 쪽에는 대부분의 데이터가 남는다. 이 과정이 반복되면 최악의 경우 O(n²)의 시간 복잡도가 발생할 수 있다.
- **First Element:** 첫 번째 원소를 피벗으로 고정하기 때문에 데이터 배열 상태에 따라 불균형한 분할이 발생할 수 있다.
- **Random Pivot:** 무작위 위치를 선택하므로 특정 위치에 대한 의존성을 줄이지만, 운이 나쁘면 불균형한 피벗이 선택될 수 있다.
- **Median-of-Three:** 서로 다른 세 위치의 값을 비교하여 중앙값을 선택하므로 극단적인 피벗 선택을 줄이고 상대적으로 균형 잡힌 분할을 유도할 수 있다.

따라서 피벗 선택 방법은 단순히 피벗의 위치를 결정하는 것뿐만 아니라 분할되는 구간의 크기와 이후 재귀 호출의 횟수에도 영향을 미친다.

### 4. 재귀적 퀵 정렬과 반복적 퀵 정렬의 실행시간 차이

- **재귀적 방식:** 분할된 왼쪽과 오른쪽 구간을 함수의 재귀 호출로 처리한다. 구현이 간결하고 퀵 정렬의 구조를 직관적으로 표현할 수 있지만, 함수 호출과 복귀 과정에서 추가적인 관리 비용이 발생한다.
- **반복적 방식:** 재귀 호출 대신 스택에 정렬할 구간의 시작과 끝 인덱스를 저장하고 반복문으로 처리한다. 재귀 함수 호출에 따른 오버헤드를 줄일 수 있지만, 스택에 구간 정보를 직접 저장하고 관리해야 한다.
- 이번 실험에서는 재귀적 방식이 1.1300ms, 반복적 방식이 1.0600ms로 측정되어 반복적 방식이 약 6.2% 빠른 결과를 보였다.
- 이러한 차이는 반복적 방식이 재귀 함수 호출에 따른 비용을 줄였기 때문일 가능성이 있다. 다만 실행시간이 매우 짧기 때문에 컴파일러 최적화, 시스템 환경, 측정 오차 등에 따라서도 결과가 달라질 수 있다.
- 따라서 이번 실험 결과만으로 반복적 방식이 항상 빠르다고 단정하기보다는, 동일한 조건에서 반복적 방식이 근소하게 빠른 실행시간을 기록했다고 해석하였다.

## 결론

이번 과제에서는 무작위 정수 데이터 n = 1,000 ~ 20,000에 대해 세 가지 피벗 선택 방법을 사용하는 퀵 정렬의 비교 횟수를 측정하고 성능을 분석하였다.

- 데이터 크기가 증가함에 따라 세 가지 방법 모두 비교 횟수가 증가하였으며, 전반적으로 n이 2배가 될 때 비교 횟수는 약 2배 이상 증가하는 경향을 보였다.
- First Element 방식은 구현이 간단하지만 피벗 선택에 따라 분할이 한쪽으로 치우칠 가능성이 있으며, 16,000개 데이터에서 280,855회로 가장 많은 비교 횟수를 기록하였다.
- Random Pivot 방식은 무작위 피벗을 통해 특정 위치에 대한 의존성을 줄였지만, 무작위 선택이 항상 균형 잡힌 분할을 보장하지는 않았다.
- Median-of-Three 방식은 세 원소의 중앙값을 피벗으로 선택하여 상대적으로 균형 잡힌 분할을 유도하였으며, 6개 데이터 크기 중 4개에서 가장 적은 비교 횟수를 기록하였다. 특히 16,000개 데이터에서 가장 큰 성능 차이를 보였다.
- 따라서 이번 실험에서는 전반적으로 Median-of-Three가 가장 효과적인 피벗 선택 방법이라고 판단하였다. 다만 Random Pivot이 일부 데이터 크기에서 더 적은 비교 횟수를 기록한 점을 통해 데이터의 분포와 피벗 선택 결과에 따라 성능이 달라질 수 있음을 확인하였다.
- 보너스 실험에서는 반복적 퀵 정렬이 재귀적 퀵 정렬보다 약 6.2% 빠르게 측정되었다. 이를 통해 동일한 정렬 알고리즘이라도 재귀 호출과 스택을 이용한 구현 방식에 따라 실행시간에 차이가 발생할 수 있음을 확인하였다.
- 모든 실험에서 정렬 결과가 오름차순으로 정상적으로 수행되었음을 확인하였다.

이를 통해 퀵 정렬의 성능은 피벗 선택 방법에 따른 분할의 균형 정도에 크게 영향을 받으며, 적절한 피벗 선택을 통해 비교 횟수를 줄일 수 있다는 것을 확인하였다. 또한 동일한 알고리즘이라도 구현 방식에 따라 실행시간에 차이가 발생할 수 있음을 확인하였다.
